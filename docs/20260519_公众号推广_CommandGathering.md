# 终端太乱，所以我给自己写了个命令管理小工具

平时开发、打包、跑脚本的时候，我经常会同时开很多个终端窗口。

前端一个，后端一个，日志一个，构建一个，部署脚本一个，临时调试再来几个。开到后面，屏幕上全是 Terminal，切来切去很乱，想找某个正在跑的命令，也要先想一下它到底开在哪个窗口里。

【配图1：主界面整体截图】

一开始我也想找现成工具解决。

但看了一圈之后发现，很多成品做得都比较重，功能很多，也很完整，只是对我来说有点“过度设计”了。我的需求其实很简单：

把常用命令收起来；  
点一下就能跑；  
不要再开一堆分散的终端窗口；  
最好连历史命令也别混在一起。

尤其是最后这一点，真的是我自己平时最烦的地方之一。

很多时候，不同任务的历史命令会混用。你在这个窗口里按上方向键，翻出来的可能是另一个窗口、另一个任务、甚至另一个项目里刚跑过的命令。命令一多，历史记录就变得很乱，找起来特别别扭。

所以后来我干脆自己写了一个小工具。

它叫 **Command Gathering**，本质上就是一个更轻量一点的命令管理器。左边是命令分组，右边是命令列表和终端标签页。常用命令可以提前整理好，需要的时候直接点一下就行。

【配图2：命令分组和命令卡片区域截图】

我在做的时候，主要抓了两个点。

第一个是，同一个命令不要重复开很多窗口。

比如日志、代理、开发服务这种命令，很多时候你不是想“再执行一次”，你只是想回到那个已经开着的窗口继续看。所以我这里做成了：第一次点击会新建一个终端 tab 并执行命令；如果这个命令已经有对应的 tab，再点就直接切回去，不会重复执行。

第二个是，每个命令窗口有自己单独的历史记录。

也就是说，这个窗口里跑过什么命令，历史就留在这个窗口里；另一个窗口跑过的内容，不会混进来。这样你在不同任务之间切换的时候，思路会清楚很多，不会一按方向键就翻出一堆不相干的历史命令。

【配图3：终端 tab 区域截图，最好能体现多个标签页】

这个工具本身没有想做得特别大。

它不是那种什么都想管的平台，也不是为了替代系统终端。更像是一个贴着自己日常习惯长出来的小工具：把零散的常用命令整理起来，把窗口管理简单一点，把历史记录隔离清楚一点，让平时那些重复但又烦人的操作顺手一些。

有时候就是这样。

不是需求有多大，而是某个小问题你每天都会遇到。次数多了，它就值得被认真解决一下。

如果你平时也经常同时跑很多命令、脚本、服务，可能会理解这种痛点。
